## Google Calendar & Google Meet Integration
---

## 1. Purpose

This document defines **how to integrate Google Calendar and Google Meet** into the existing Online Clinic system to automatically generate meeting links for doctor–patient appointments.

Scope of this document:

* Generate Google Meet links automatically
* Attach them to appointments
* Allow doctor & patient to join meetings
* **No payment gateway**
* **No notification system** (email/SMS/WhatsApp will be added later)

---

## 2. High-Level Design Principles

### 2.1 Google Meet as External Service

* Google Meet is treated strictly as an **external video service**
* The system only:

  * Generates a Meet URL
  * Stores the Meet URL
* The system does **NOT**:

  * Handle audio/video
  * Track participants
  * Receive join/leave callbacks
  * Detect meeting end

---

### 2.2 System-Controlled Meeting Generation

* Doctors must **NOT** manually paste or edit meeting links
* Meeting links are **always generated by backend logic**
* Meeting generation happens automatically after appointment creation

---

### 2.3 Future-Proofing

* Payment gateway (bKash) will be added later
* No refactor should be required when payment is introduced
* Google Meet logic must remain independent of payment logic

---

## 3. Technologies Involved

* **Backend:** Node.js + Express
* **Database:** PostgreSQL
* **Auth:** JWT (existing system auth)

### Google APIs

* **Google Calendar API** (primary API used)
* **Google Meet** (generated indirectly via Calendar)

⚠️ **Important clarification**
There is **NO direct Google Meet API usage**.
Google Meet links are generated **only through Google Calendar API**.

---

## 4. Appointment Status Model

Extend appointment statuses as follows:

```text
upcoming   → appointment created, meeting not yet ready
ready      → meeting link generated, joinable
completed  → consultation done, prescription saved
cancelled  → cancelled by patient or doctor
```

> ⚠️ Note
> Payment integration later will insert:
> `pending_payment → ready`
> No Google Meet logic should be tied to payment.

---

## 5. Database Changes

### 5.1 Appointments Table

Add the following fields:

```sql
ALTER TABLE appointments
ADD COLUMN meeting_link TEXT,
ADD COLUMN calendar_event_id TEXT,
ADD COLUMN meeting_provider VARCHAR(20) DEFAULT 'google_meet';
```

**Field purpose:**

* `meeting_link` → Google Meet URL
* `calendar_event_id` → Used for future update/cancellation
* `meeting_provider` → Extensible (Zoom, etc. later)

---

## 6. Google Cloud & OAuth Setup

### 6.1 Authentication Method (MANDATORY)

* **OAuth 2.0 is required**
* **API keys must NOT be used**
* OAuth is required because:

  * Calendar access is private
  * Meet links are created on behalf of a Google account

---

### 6.2 Required OAuth Scope

```text
https://www.googleapis.com/auth/calendar
```

No other scopes are required.

---

### 6.3 Environment Variables (Already Provided)

The backend environment already contains:

```env
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=http://localhost:5000/auth/google/callback
GOOGLE_CALENDAR_TIMEZONE=Asia/Dhaka
```

These must be used for OAuth-based Calendar API access.

---

## 7. OAuth Authorization Flow (REQUIRED)

Before any meeting can be created, the backend must obtain OAuth tokens.

### 7.1 Required Backend Routes

#### Start OAuth Authorization

```http
GET /auth/google
```

* Generates Google OAuth URL
* Redirects user to Google login
* Used once by system admin / developer

---

#### OAuth Callback

```http
GET /auth/google/callback
```

* Receives `code` from Google
* Exchanges it for:

  * `access_token`
  * `refresh_token`
* Stores tokens securely (database or encrypted storage)

⚠️ This authorization is required **only once**.
All future Meet generations use the stored refresh token.

---

### 7.2 Token Handling Rules

* Store `refresh_token` permanently
* Auto-refresh access tokens
* Never expose tokens to frontend
* All Calendar API calls must use OAuth tokens

---

## 8. When to Generate the Meeting

### Trigger Point (IMPORTANT)

The meeting must be generated **immediately after appointment creation**, once all validations pass.

```text
Appointment created
→ Generate Google Calendar event
→ Generate Google Meet link
→ Update appointment
→ Status = ready
```

Do **NOT**:

* Wait for doctor action
* Wait for appointment time
* Require manual meeting creation

---

## 9. Google Calendar Event Creation Flow

### 9.1 Backend Responsibility

When an appointment is created:

1. Authenticate with Google using stored OAuth tokens
2. Create a Google Calendar event
3. Request Google Meet conference data
4. Add doctor and patient as attendees
5. Save returned data in database

---

### 9.2 Calendar Event Requirements

Each event must include:

* Start time (appointment start)
* End time (start + 30 minutes)
* Timezone: `Asia/Dhaka`
* Summary: `Online Consultation`
* Description:

  * Doctor name
  * Patient name
  * Appointment ID
* Attendees:

  * Doctor email
  * Patient email
* Conference data (Google Meet)

---

### 9.3 Conference (Meet) Creation

Use Calendar API’s `conferenceData.createRequest`.

Result:

* Google Meet URL generated
* Calendar event created
* Google handles attendee invitations internally

---

### 9.4 Persisting Data

From Google API response, store:

* `meeting_link` → Meet URL
* `calendar_event_id` → Event ID

Update appointment:

```text
status = ready
meeting_link = <meet_url>
calendar_event_id = <event_id>
```

---

## 10. Backend API Responsibilities

### 10.1 Appointment Creation Endpoint

After existing validations:

* Create appointment (status = upcoming)
* Generate Google Calendar event
* Generate Google Meet link
* Update appointment to status = ready
* Return appointment with meeting link

---

### 10.2 Appointment Fetch APIs

For both Doctor and Patient dashboards, include:

* `meeting_link`
* `status`

---

## 11. Frontend Integration

### 11.1 Join Meeting Button

For appointments where:

```text
status = ready
```

Show a **Join Meeting** button.

```tsx
<a href={meeting_link} target="_blank" rel="noopener noreferrer">
  Join Google Meet
</a>
```

---

### 11.2 UI Restrictions

* Do NOT allow editing meeting links
* Do NOT embed Google Meet
* Do NOT expose calendar IDs or tokens

---

## 12. Cancellation Handling (Basic)

If an appointment is cancelled:

* Update status = cancelled
* Do NOT regenerate meeting links
* (Optional later) delete calendar event using `calendar_event_id`

---

## 13. What NOT to Implement (Strict)

The following are **explicitly out of scope**:

* ❌ API key usage
* ❌ Real-time participant count
* ❌ Join/leave callbacks
* ❌ Meeting end detection
* ❌ Embedded Meet iframe
* ❌ Video/audio handling
* ❌ Live consultation state tracking

---

## 14. Security Notes

* OAuth tokens must be stored securely
* Never log tokens
* Never expose tokens to frontend
* Meeting link visible only to assigned doctor & patient

---

## 15. Testing Checklist

* Appointment creates successfully
* Google Meet link generated
* Appointment status becomes `ready`
* Meet link opens correctly
* Doctor and patient can join
* Prescription flow still works
* No manual meeting input exists

---

## 16. Final Notes for Implementer

* Use **Google Calendar API + OAuth 2.0 only**
* Do NOT use API keys
* Treat Google Meet as **link generation only**
* Keep logic isolated and clean
* Follow this document strictly
